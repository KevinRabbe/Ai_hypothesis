# Large-Scope Result Contract v0

## Purpose

This contract validates that a large-scope relevance result artifact is the experiment we intended to run before anyone interprets its neural outcome.

It is not a scientific win/fail rule.

The validator checks artifact identity, causal comparability, paired completeness, checkpoint identity and cost accounting, then emits a normalized readout with:

```text
scientific_decision = NOT_ASSIGNED
```

No effect-size or p-value threshold is converted into a population-advantage claim here.

## Canonical development shape

The default development contract expects:

```text
split = development
widths = 1, 4, 16
modes = same_worker, diverse_workers
```

Both worker modes must be present because the architecture-specific diversity contrast is paired on the same worlds and exact inspection prefixes.

## Hard validation invariants

The validator requires:

- benchmark version matches `large-scope-relevance-v0`;
- one positive world count + one negative world count closes to the declared world count for every condition and paired row;
- the condition summaries form the complete mode × width matrix;
- the paired summaries contain exactly one pair for every world at every width;
- same-worker and diverse-worker target coverage are identical at each width;
- paired target-inspected counts agree with the condition summaries;
- local neural evaluation accounting equals `world_count × mode_count × sum(widths)`;
- checkpoint metadata count equals population width;
- every worker has a unique stable `weights-sha256-*` learned-state identity;
- largest diverse width does not exceed the loaded population;
- all reported paired metric values are finite when present.

## Width-1 causal sanity check

The benchmark uses the same deterministic base checkpoint for both modes at width 1.

Therefore width 1 is not merely expected to be similar: it is a causal identity control.

The validator rejects width-1 artifacts with:

- any same-only or diverse-only retrieval event;
- non-zero paired retrieval delta;
- non-zero paired target-rank delta;
- non-zero target-evidence delta;
- non-zero distractor-evidence delta;
- non-zero target-minus-distractor gap delta;
- non-zero positive- or negative-world candidate-evidence delta,

outside a small configurable numerical tolerance.

A failed width-1 identity check invalidates interpretation of wider diversity effects until the cause is understood.

## Stable worker identity

The result artifact records the `checkpoint_id` generated by `HomogeneousWorkerBank`.

That identity hashes exact learned tensor bytes together with structural worker configuration, so moving or renaming a checkpoint file does not change worker identity.

Duplicate learned-state identities are rejected because a nominal 16-worker population containing duplicated weights would not represent 16 independently weighted workers.

## CLI

Validate a canonical development result:

```powershell
python -m ai_hypothesis.large_scope.validate_result `
    --input results\large_scope_relevance_v0\development.json `
    --output results\large_scope_relevance_v0\development.validated.json
```

The normalized output is intentionally interpretation-ready rather than decision-making. It exposes per-width paired retrieval, rank, evidence-gap, false-positive and standard-error fields while leaving the scientific conclusion unassigned.

## Scientific boundary

Passing this validator proves only that:

- the result artifact is internally coherent;
- the intended same-scope causal controls were actually present;
- the paired comparison is complete;
- immutable worker identities and compute accounting are available;
- width 1 behaves as the identity control it is supposed to be.

It does not prove that independent weights help, that scope scaling is useful, or that the population architecture beats a dense baseline.
